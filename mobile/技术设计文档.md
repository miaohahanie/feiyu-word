## 1. 总体架构

```text
┌─────────────────────────────┐
│ 电脑端「单词桌宠」(Electron)  │
│                             │
│  · 本地词库 word-pet-data    │
│  · SM-2/FSRS 调度           │
│  · 新建「手机同步服务」       │
│     - HTTP 局域网服务        │
│     - 二维码 / 6 位配对码     │
│     - 设备 token 鉴权        │
│     - 双向同步 API           │
└──────────────┬──────────────┘
               │ 同一 WiFi / 局域网 HTTP
┌──────────────▼──────────────┐
│ 手机端 App (Flutter)         │
│                             │
│  · 扫码 / 手动输入配对        │
│  · SQLite 本地词库           │
│  · 轻量复习（认识/模糊/不认识）│
│  · 本地提醒（随时提醒）        │
│  · 离线可用，联网回传进度      │
└─────────────────────────────┘
```

- **电脑是数据源**：词条、释义、音标、例句、词本结构以电脑端为准。
- **手机是复习终端**：手机只改变"复习进度"，不新建/删除词条（MVP）。
- **同步是事件驱动**：手机把复习行为作为"事件"上传，电脑端按 SM-2 算法重算并回传权威状态，避免两端算法漂移。

## 2. 电脑端设计

### 2.1 新增模块

建议在 `main.js` 之外新增模块，主进程引用：

```text
main.js                # 原主进程入口，注册 IPC 与启动/停止同步服务
sync/sync-server.js    # HTTP 服务：路由、配对、鉴权、同步接口
sync/sync-store.js     # 配对设备、墓碑（删除记录）、事件去重、updatedAt 维护
sync/qr.js             # 生成二维码（如使用 qrcode npm 包）
renderer/index.html    # 设置页新增「手机同步」卡片
renderer/app.js        # 同步服务状态 UI、二维码展示、设备管理
```

### 2.2 启动方式

- 用户可在「设置 → 手机同步」页**开启/关闭**服务；
- 默认关闭，开启后监听 `0.0.0.0:8787`（可配置端口）；
- 启动时生成：
  - 6 位配对码（`000000-999999`），有效期 10 分钟；
  - 本机局域网 IP 列表（优先选择活跃网卡）；
  - 二维码内容（自定义 scheme，见 2.4）。
- 电脑端不主动连接公网；服务仅在电脑运行时可用。

### 2.3 数据扩展

现有 `word-pet-data.json` 增加：

```json
{
  "syncDevices": [
    {
      "deviceId": "uuid",
      "name": "Xiaomi 14",
      "tokenHash": "sha256(...)",
      "pairedAt": 1725259200000,
      "lastSyncAt": 1725259800000
    }
  ],
  "syncServer": {
    "enabled": true,
    "port": 8787,
    "pairingCode": "123456",
    "codeExpiresAt": 1725259800000
  },
  "syncTombstones": [
    { "bookId": "book-cet6", "word": "oldword", "deletedAt": 1725259200000 }
  ]
}
```

每个词条增加同步字段（软件删除时保留在库中但标记删除，用于增量同步）：

```json
{
  "word": "abandon",
  "meaning": "v. 放弃, 抛弃…",
  "phonetic": "/ə'bændən/",
  "examples": [],
  "reps": 3,
  "ease": 2.5,
  "interval": 6,
  "lapses": 0,
  "lastRating": 8,
  "nextReview": 1725800000000,
  "mastered": false,
  "history": [
    { "id": "evt-uuid-1", "date": "2026-09-01T12:00:00+08:00", "rating": 8 }
  ],
  "updatedAt": 1725259800000,
  "deleted": false
}
```

- `updatedAt`：词条任何变化（复习、编辑、删除）时更新；
- `history[].id`：复习事件唯一 ID，用于手机 ↔ 电脑去重；
- `deleted`：软删除，同步完成后可长期保留，用于增量下发；若设备全部同步后再清理（可选）。

### 2.4 配对与鉴权

**配对**：

- 手机扫码内容：`wordpet://pair?host=192.168.1.5&port=8787&code=123456`
- 手机 `POST /api/pair`，携带 `code`；
- 电脑校验有效期后返回：
  ```json
  {
    "deviceId": "uuid",
    "token": "64 位随机 token",
    "serverTime": 1725259200000,
    "books": [
      { "id": "book-cet6", "name": "六级词汇 · 内置", "builtin": true, "count": 1945 }
    ]
  }
  ```
- 电脑保存 `tokenHash`（SHA-256），不保存明文 token。

**鉴权**：

- 后续请求头部：
  ```
  Authorization: Bearer <token>
  Device-Id: <deviceId>
  ```
- 未知/过期设备返回 401；同一设备重复配对返回原 deviceId（幂等）。

### 2.5 同步 API 定义

#### `GET /api/health`

```json
{ "ok": true, "appVersion": "0.3.2", "serverTime": 1725259200000 }
```

#### `POST /api/pair`

请求：

```json
{ "code": "123456" }
```

响应见 2.4；错误：`400` 参数错误，`401` 配对码错误/过期。

#### `GET /api/books`

响应：

```json
{
  "books": [
    { "id": "book-cet6", "name": "六级词汇 · 内置", "builtin": true, "count": 1945 }
  ]
}
```

#### `GET /api/sync?book=<id>&since=<epochMs>`

- `since=0` 表示全量；
- 响应：

```json
{
  "serverTime": 1725259800000,
  "book": { "id": "book-cet6", "name": "六级词汇 · 内置" },
  "words": [
    {
      "word": "abandon",
      "meaning": "v. 放弃, 抛弃…",
      "phonetic": "/ə'bændən/",
      "examples": [ { "text": "...", "translation": "...", "source": "剪贴板" } ],
      "reps": 3,
      "ease": 2.5,
      "interval": 6,
      "lapses": 0,
      "lastRating": 8,
      "nextReview": 1725800000000,
      "mastered": false,
      "updatedAt": 1725259800000,
      "deleted": false
    }
  ],
  "tombstones": [
    { "word": "oldword", "deletedAt": 1725259200000 }
  ]
}
```

#### `POST /api/sync`（手机上传统计事件）

请求：

```json
{
  "bookId": "book-cet6",
  "deviceId": "uuid",
  "events": [
    {
      "eventId": "evt-uuid-1",
      "word": "abandon",
      "rating": 8,
      "createdAt": 1725259700000
    }
  ]
}
```

响应：

```json
{
  "serverTime": 1725259800000,
  "accepted": 1,
  "ignored": 0,
  "conflicts": [],
  "changedWords": [
    {
      "word": "abandon",
      "reps": 4,
      "ease": 2.6,
      "interval": 12,
      "lapses": 0,
      "lastRating": 8,
      "nextReview": 1725900000000,
      "mastered": false,
      "updatedAt": 1725259800000
    }
  ]
}
```

#### 其他

- `POST /api/sync` 请求体上限建议 5 MB，单次事件不超过 500 条；
- `DELETE /api/device/<deviceId>`：电脑端解除配对（手机端也可在设置里退出）。

### 2.6 冲突与合并规则（确认版）

1. **词条元数据（释义/音标/例句/词本结构）**：以电脑端为准，手机端不修改。
2. **复习进度**：以“事件”为准——
   - 手机在评分时生成 `eventId`（UUID）；
   - 电脑端收到事件后，先用 `eventId` 去重（已在 `history` 存在则忽略）；
   - 未处理事件由电脑端调用与手机端**相同**的 SM-2 算法重算 `reps/ease/interval/nextReview/mastered`；
   - 每词 `updatedAt` 取事件时间与现有时间较大者；
   - 因此不会出现"两端状态不同步"。
3. **历史记录**：按 `eventId` 合并去重，两端都不会丢。
4. **删除**：手机端收到 `deleted=true` 后本地软删除/移除；手机不会新建或删除词条。

### 3.4 手机端核心流程

#### 首次使用 / 配对

1. 打开 App → 进入「设置」；
2. 点击「扫码配对」→ `mobile_scanner` 扫描电脑二维码；
3. 解析 `wordpet://pair?host=...&port=...&code=...`；
4. 调用 `POST /api/pair`；
5. 保存 `deviceId`、`token`、服务器地址；
6. 选择要同步的词本 → 执行首次全量同步。

> 备用：手动输入 `IP + 端口 + 6 位配对码`。

#### 下拉同步 / 自动同步

- 打开 App、切换词本、点击同步时触发；
- 步骤：
  1. `GET /api/sync?book=<id>&since=<本地游标>` 拉取增量；
  2. 解析并 upsert 到 SQLite（含 `deleted` 墓碑处理）；
  3. 将 `review_events.synced=0` 的事件打包成 `POST /api/sync` 上传；
  4. 用响应中的 `changedWords` 覆盖本地词条状态；
  5. 将已确认事件标记 `synced=1`，必要时清理；
  6. 保存新的游标 / `serverTime`；
  7. 重新调度提醒。

#### 复习过程

1. 从 SQLite 取到期词（`deleted=0 AND mastered=0 AND nextReview<=now`），按 `nextReview` 排序；
2. 显示：单词 → 音标 →（可选）例句/译文；
3. 点击「显示答案」显示中文释义；
4. 点击「认识 / 模糊 / 不认识」：
   - 用 Dart 版 SM-2（与电脑端一致）计算新状态；
   - 生成 `eventId` 并写入 `review_events`；
   - 更新本地词条；
   - 立即重新调度提醒；
5. 队列为空时显示今日总结。

### 3.5 Dart 版调度算法（与电脑端一致）

手机端必须**逐字移植**现有 `renderer/scheduler.js`：

- 评分映射：`认识=8`、`模糊=4`、`不认识=1`；
- `q<3`：重置并 10 分钟 / 4 小时后再出现；
- `q>=3`：1 天 → 6 天 → `interval * ease`；
- `ease` 更新公式与下限 1.3 一致；
- `mastered`：最近 3 次≥8 且 interval≥21 天；
- 建议为 Dart 版写与电脑端相同的**单元测试样例**（如 `abandon` 多次评分序列），确保两端结果一致。

### 3.6 提醒调度（随时提醒）

- 每次同步、每次评分、每天打开 App 时，重新计算未来 7 天的提醒计划；
- 从 `words` 表取 `nextReview > now AND nextReview <= now+7天` 的到期词；
- 按**15 分钟粒度聚合**：
  - 同一时段内到期的多个词合并为一条：
    - 默认标题：`单词桌宠复习提醒`
    - 默认内容：`有 N 个词到期，来复习一下吧`
- 使用 `flutter_local_notifications.zonedSchedule` 调度（Android 12+ 需要 `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` 权限）；
- 若精确闹钟权限被拒，降级为 `inexact`，并依靠 `workmanager` 每小时兜底检查；
- 单个设备最多调度 100 条；超过时，调度"每天 20:00 一条汇总"作为兜底（可配置）；
- 默认不展示单词内容（隐私），设置中可开启"通知预览显示一个单词"；
- 复习完成/重新同步后，取消旧通知并重新调度。

## 4. 同步时序（一次完整同步）

```text
手机                                   电脑
 │  GET /api/sync?since=cursor        │
 │ ─────────────────────────────────→│  · 查询增量词条
 │ ←─────────────────────────────────│  · 返回 words/tombstones
 │  upsert 本地 DB                    │
 │  POST /api/sync (pending events)   │
 │ ─────────────────────────────────→│  · eventId 去重
 │                                    │  · 按 SM-2 重算状态
 │                                    │  · 更新统计数据
 │ ←─────────────────────────────────│  · changedWords / serverTime
 │  覆盖本地状态、标记事件已同步       │
 │  重新调度提醒                       │
```

## 5. 错误处理与降级

| 场景 | 行为 |
| --- | --- |
| 电脑关闭 / 手机不在同一 WiFi | 提示“无法连接电脑”，保留本地数据；复习与提醒照常 |
| 配对码过期 | 提示重新刷新电脑端二维码 |
| token 失效 | 清除本地配对信息，要求重新扫码 |
| 同步失败 | 本地事件保留 `synced=0`，下次重试；不覆盖本地数据 |
| 精确闹钟权限被拒 | 降级为 inexact + workmanager 每小时兜底 |
| 词本被电脑端删除 | 手机端按 `tombstone`/删除标记移除，或提示词本已不存在 |

## 8. 风险与待讨论

1. **国内手机后台限制**：部分厂商可能拦截通知/后台任务，需要引导用户设置自启动与电池白名单；无法保证 100% 到达。
2. **精确闹钟**：Android 12+ 需要用户授予精确闹钟权限；被拒只能降级为约 15 分钟误差。
3. **同一时间大量到期词**：需合并通知，避免通知轰炸。
4. **数据迁移**：现有 `word-pet-data.json` 中历史记录没有 `eventId`，首次同步要做兼容（服务端自动生成稳定 ID）。
5. **二维码生成依赖**：电脑端需要新增 `qrcode` npm 依赖（MIT，轻量）。
6. **Windows 防火墙**：首次开启服务可能被防火墙拦截，UI 需提示用户允许"专用网络"。
